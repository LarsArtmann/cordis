## d) TOTALLY FUCKED UP

Honest accounting of this session's own failures (all resolved; listed so they teach):

1. **Declared the Go suite green after a single passing race run — it was flaky.** The golden test had nondeterministic sibling-unload order (Go map iteration in `notifyDependents`). Only a later re-run with `-count=5` (mimicking nothing — luck) exposed it. Root-caused and fixed with a uid sort, then verified `-count=10`. **Lesson: one green race run proves nothing; concurrency suites need repeated runs before "done".**
2. **My golden runner initially dropped `.Inject(deps)` on the floor** — plugins were started with no dependencies at all, so withdrawal unmounted nothing. I burned several debug cycles writing scratch reproductions before re-reading my own runner and spotting the one-line omission. The bug was in new test code, not the framework; I should have read the runner first.
3. **Shell discipline meltdown on `isolate_test.go`:** a heredoc append ran from the wrong cwd (append succeeded via absolute path, `gofmt` failed), I re-appended and got duplicate test functions, then "fixed" it with `head -188` which truncated mid-function leaving literal `EOF` garbage. Ended in `git restore` + one clean append. Wasted three round trips that `trash`-proof, cwd-explicit commands would have avoided.
4. **Zig public-API naming collision:** introduced `pub fn plugin(...)` without checking it shadowed the `plugin` parameter/locals in `startPlugin`/`injectPlugin` — instant compile errors, rename to `TypedPlugin`. A 10-second grep would have caught it.
5. **First drafts shipped broken:** a Zig test referencing a nonexistent `counterHolder()`; a Go stdctx test that deadlocked _by construction_ (`<-done` inside the apply body can never fire before apply returns); a Rust golden runner with dead scaffolding (`p_config`, unused `PluginEntry` plumbing); `GOLDEN_UPDATE` that read `expected.txt` before writing it, then a "fix" that deleted the write entirely. All caught before merge — but each was preventable by thinking the control flow through once more before writing.
6. **Zig `ApplyFn` signature churn:** changing the apply signature to take the plugin pointer broke every existing test apply fn. Justified by the bridge design, but I decided it mid-flight rather than designing the typed-plugin bridge up front; a moment of up-front design would have avoided the rework.

Nothing in this list remains broken. No data loss, no broken build at any commit point, no unrecovered state.

Capture it in AGENTS.md as _the_ pattern for Zig runtime plugin plumbing (partially done).
